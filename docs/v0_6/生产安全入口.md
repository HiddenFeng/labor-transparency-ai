# v0.6 生产安全入口与反滥用基线

日期：2026-09-14。状态：实现并测试的**生产入口候选**，不是已经部署的生产服务。 当前 GitHub Pages 只读公益站点已公开，但它不运行此生产ASGI入口，也不接收私密数据。

## 1. 为什么不能直接把本地服务暴露到公网

`app.server:app` 的默认配置仍是本地验证模式：只接受回环/TestClient主机，并用 `X-Ltp-Client: local-demo` 作为本地变更请求标记。它适合本机功能验证，不是公网认证或CSRF机制。生产模式必须使用独立入口 `app.production:app`，并且只有在完整生产环境变量通过预检后才允许构建应用。

## 2. 生产入口现在具备什么

生产配置默认失败关闭，要求：

- `LTP_RUNTIME_PROFILE=production` 明确声明；本地模式不会因环境变化自动升级为生产。
- `LTP_DB` 使用源码目录之外的绝对路径，避免把真实运行数据库打进代码包或Git。
- `LTP_ADMIN_TOKEN` 与 `LTP_SECURITY_SECRET` 均至少32字符，必须彼此独立，并拒绝常见示例/占位值。
- `LTP_ALLOWED_HOSTS` 只接受精确主机名，不支持 `*`；`LTP_ALLOWED_ORIGINS` 只接受精确HTTPS Origin，且Origin主机必须同时在Host白名单内。
- 若使用反向代理，必须显式列出 `LTP_FORWARDED_ALLOW_IPS`；禁止 `*` 信任所有转发头。
- 生产管理API必须显式设置 `LTP_ADMIN_ALLOWED_IPS`，且只接受精确IPv4/IPv6地址，不接受 `*`、CIDR或主机名；不配置即拒绝启动生产配置。这一门用于把管理员令牌之外再加一层受限运营网络边界，不替代后续独立运营身份或MFA。
- 生产附件上传默认 `LTP_ATTACHMENT_UPLOADS=disabled`；只有显式选择 `clamav` 且 `LTP_CLAMSCAN_PATH` 指向真实、绝对、可执行文件时才允许接收附件。扫描器缺失、报错、超时或判定感染都必须失败关闭，不能先保存后补扫。

请求层已加入：

1. 精确Host检查；
2. 生产HTTPS强制；
3. 变更请求必须来自精确允许的Origin；
4. `/api/admin...` 在任何管理员凭据判断之前先检查受限运营网络IP，不在 `LTP_ADMIN_ALLOWED_IPS` 中即403；
5. HttpOnly + Secure + SameSite=Strict会话Cookie；
6. 与会话绑定、由服务端安全密钥HMAC派生的CSRF令牌；登录、注册、退出造成会话轮换后旧CSRF令牌立即失效；
7. SQLite持久固定窗口限流，分为读取、普通变更和管理员请求三档；
8. 最小安全审计：客户端网络标识先用服务端密钥HMAC，不保存原始IP，不记录请求正文、Cookie、Authorization或管理员凭据；
9. CSP、HSTS、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy、Cross-Origin-Resource-Policy；
10. 请求体仍有3MB硬上限；原有账号登录尝试节流继续存在；
11. `/api/health` 只返回非敏感运行状态，不返回数据库路径、用户内容或任何安全密钥；
12. 生产附件必须在入库前通过格式门与恶意文件扫描；只有 `CLEAN` 才能保存。扫描通过只表示文件安全检查通过，不提升材料真实性或证据等级。

前端在本地模式继续使用 `X-Ltp-Client`；在生产模式会从 `/api/config` 获取当前会话CSRF令牌，并仅在变更请求中提交 `X-Ltp-Csrf`。两种边界不会混用；本地客户端标记不能替代生产CSRF。

## 3. 反向代理推荐边界

首选结构：

`Internet → Caddy/TLS → 127.0.0.1:8080 Uvicorn → SQLite独立数据卷`

应用进程仍只绑定回环；公网端口只由反向代理监听。示例见 `deploy/Caddyfile.example`、`deploy/production.env.example` 和 `deploy/labor-transparency.service.example`。如果Caddy与应用同机，则 `LTP_FORWARDED_ALLOW_IPS=127.0.0.1`；Uvicorn也必须只信任这个地址的代理头。不能为了省事配置 `--forwarded-allow-ips='*'`。这些文件目前只是可审查模板，没有被安装到本机或任何服务器。

配置完成后先执行：

```sh
python scripts/check_production_config.py
```

它只做失败关闭的配置检查，不部署、不创建DNS、不申请证书、不启动公网监听，也不会打印安全密钥或管理员凭据。

## 4. 已验证边界

生产安全专项现在覆盖缺失生产声明、源码内数据库、弱/复用Secret、通配Host、HTTP Origin、不受限代理信任、缺失或非法管理员网络白名单等失败关闭路径；管理员API从非允许来源访问会在凭据判断之前直接403。完整Python回归在3.9.6与3.12.14上均为285项通过，Node页面/离线逻辑103项通过；既有真实回环HTTP 106项、真实Chrome桌面/窄视口和GLEIF单次联网证据继续保留为已接受证据。

真实外部代理已从“自建测试代理”提升到 **Caddy 2.11.4**：Caddy配置先经真实 `caddy validate`，随后回环TLS反向代理到生产ASGI；临时私有CA由客户端验证，健康检查200、错误Host 403、缺CSRF 403、正确同源CSRF 200，安全Cookie/HSTS/CSP经代理链仍存在；演练后无持久Caddy服务和遗留监听。机器证据为 `qa/v0_6/caddy-staging.json`。

系统级恢复在当前Mac上也有真实证据：一次性用户级launchd `KeepAlive` 管理生产后端，受控终止首个PID后出现替换PID并恢复生产健康，最近一次恢复约1.2秒；演练随后bootout并清理监听。macOS隐私边界禁止LaunchAgent直接读取Downloads项目时，没有降低权限，而是使用权限收紧的临时staging副本。机器证据为 `qa/v0_6/launchd-supervision.json`。

真实恶意文件扫描不再只是适配器模拟。当前Mac安装ClamAV 1.5.4，FreshClam运行后存在真实 `daily.cvd`，`clamscan --version` 显示签名版本28123；普通合成文本判定CLEAN，标准无害EICAR测试签名判定INFECTED。真实clamscan进一步接入生产附件路径：CLEAN附件可入库并记录 `scan_engine=clamav`，EICAR在入库前拒绝且数据库附件数不增加。机器证据为 `qa/v0_6/clamav-real.json`。

## 5. 仍未完成，不能扩大结论

当前证据已支持“生产入口、真实本机反向代理、当前Mac进程恢复、真实ClamAV扫描和管理员受限网络门均具备基础运行能力”，但仍不支持“已经生产级公网运营”。剩余发布门主要是：

- 正式/公共CA证书签发与自动续期、DNS以及目标服务器防火墙；
- 目标生产服务器上的服务账号、文件权限、systemd/容器生命周期与故障恢复；本机launchd结果不能替代目标OS验收；
- FreshClam长期定时更新、镜像长期可用性、main/bytecode数据库完整生命周期与并发扫描性能；
- 管理员凭据进入真正的Secret Manager/受限环境文件，并增加独立运营身份/MFA；IP白名单只是额外网络边界；
- 多副本统一限流后端；当前SQLite限流仍是单节点方案；
- 外部监控、告警、日志留存，异地加密备份、保留/销毁策略、RPO/RTO和容量压测；
- 公开内容更系统的PII、版权/授权复核；
- 多来源长期可靠性以及真实申诉渠道的受控提交与回执状态机；
- 独立项目Git边界、GitHub/Sites/域名和最终公网浏览验收。
