## 无人值守公司资料自动研究

生产主链现为：

`用户创建公司 -> D1 QUEUED -> Cloudflare Queue -> 串行多源采集 -> 确定性信任规则 -> AUTO_READY* -> 安全公开机器情报 -> 24h 刷新/旧策略即时迁移 -> 失败/DLQ 自动退避恢复`。

自动公司资料已覆盖 GLEIF、SEC EDGAR、Wikidata、NLRB、OSHA、DOL WHD、FMCS、DOL OLMS、USAspending 等公开来源；OpenCorporates / Open Supply Hub 继续保持 fail-closed，可选 token/订阅/许可条件未满足时不会启用。普通用户创建公司后不需要某个命名运营者进行 enqueue、run、source binding 或 review。Python back office 仍可做离线审计和复杂显式绑定实验，但不是网站正常运行或资料展示的生产门。

机器发布边界严格固定：

- `MACHINE_VERIFIED_REFERENCE`：初始只允许唯一精确 GLEIF 法律名称 + 可解析公司国家提示 + GLEIF 国家一致 + 有效 ISO-17442 LEI 校验码；兼容的 SEC 参考还要求已机器绑定的美国身份和有效 10 位 CIK。
- `SOURCE_SIGNAL`：劳动/执法/工会/停工/公开记录的精确名称命中只允许表达“来源存在同名记录/数量/程序上下文”，保留各机构记录的原始法律与程序语义。
- 主体歧义、国家冲突、无效结构化标识、Wikidata/二级上下文、未绑定供应链关系与法律责任判断全部失败关闭为候选或未知。
- 每次刷新完整重算机器情报；当前来源不再支持的事实自动撤回/降级，不依赖人工删除。

无人值守恢复也已闭环：主 Queue 每批 1 条、并发 1、最多 5 次重试；耗尽后进入独立 DLQ，同一 Worker 作为 DLQ consumer 将失败状态持久化到 D1；5 分钟与每日 trigger 按 `failureCount` 从 30 分钟起指数退避、最高 8 小时自动重新投递，同时恢复漏单、陈旧 `COLLECTING` 与旧策略记录。`/api/research/health` 公开聚合健康状态，但不泄露 raw records。

生产验证不是合成判断：GitHub-hosted E2E run `35046956907` 从项目自有域名创建隔离 Starbucks QA 公司；`2026-09-16T02:10:35.822Z` 创建后于 `02:10:37.671Z` 进入 Queue 研究，约 1.85 秒完成为 `AUTO_READY_WITH_SOURCE_GAPS`，得到 6 个机器参考事实、4 个来源信号、9/11 来源成功且 `reviewRequired=false`，随后普通用户负向 ballot mutation 也通过。验收后精准删除 QA company/research/ballot 共 3 条记录。

更关键的是既有真实用户数据也已自动迁移：`星宇股份有限公司` 无需任何私有 research run/review 就迁移到 `auto-intelligence-0.8.2` / `AUTO_READY_WITH_SOURCE_GAPS`。由于当前来源不足以满足机器身份绑定门槛，系统正确保持 `NO_VERIFIED_REFERENCE`、0 个机器参考事实/0 个来源信号，而不是强行猜测；该公司的真实负向社区反馈 1 条仍完整保留。浏览器在 canonical 域名验证公司卡片、无人值守状态、方法页口径与真实社区反馈均正常，最终页面 `console_errors=0 / network_errors=0 / page_errors=0`。机器证据见 `qa/v0_8/autonomous-company-intelligence-v082-production.json` 与 `qa/v0_8/verification.json`。

## 仍然不能扩大成的结论

- 不能说“全球所有公司的全部数据已经自动完整收集”；来源覆盖仍受司法区、公司类型、许可、数据公开程度和接口稳定性限制。

- 中国大陆稳定生产服务当前仍未承诺；原因是没有采用经过大陆稳定性/合规验收的本地入口，而不是当前发布仍等待腾讯云账号或支付资料。
